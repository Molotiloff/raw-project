# Лабораторный шлюз

Учебный прототип на синтетических данных. Это не ПТС ОРМ, не полная реализация проекта указания и не подтверждение соответствия. Используйте только изолированный локальный кластер; публичный доступ запрещён.

## Развёртывание в локальном Kubernetes

Необходимы Docker, kubectl, локальный кластер с PVC и установленным StorageClass. Манифест использует ClusterIP и не создаёт внешний балансировщик или ingress. Сетевые политики работают только при поддержке CNI; доступ через port-forward не является проверкой изоляции сети.

1. Соберите образ из папки `lab-gateway`: `docker build -t iar-lab-gateway:local .`. Загрузите его в выбранный кластер (например, `kind load docker-image iar-lab-gateway:local` для kind). В Docker Desktop образ может быть доступен напрямую.
2. `kubectl apply -f k8s/lab.yaml` создаст namespace и ресурсы. Pods будут ожидать Secret.
3. Создайте локальные файлы `postgres-password`, `database-url` и `clients-json` с ограниченными правами, не добавляйте их в Git. Пароль в URL должен совпадать с паролем PostgreSQL. Пример содержимого clients-json:

```json
[{"name":"reader","token":"replace-with-a-long-random-reader-token","objects":["demo"]},{"name":"producer","token":"replace-with-a-long-random-producer-token","objects":["demo"],"producer":true,"metrics":true}]
```

Пример URL: `postgresql://gateway:YOUR_PASSWORD@postgres:5432/gateway`. Используйте пароль из букв и цифр или URL-кодируйте специальные символы.

4. `kubectl -n iar-lab create secret generic lab-secrets --from-file=postgres-password --from-file=database-url --from-file=clients-json`
5. Дождитесь готовности: `kubectl -n iar-lab rollout status deployment/postgres` и `kubectl -n iar-lab rollout status deployment/gateway`.
6. Для локального доступа: `kubectl -n iar-lab port-forward svc/gateway 8000:8000`. Запросы выполняйте только на своём стенде с заголовком `Authorization: Bearer <token>`.

Пример: `POST /events` с JSON `{"object_id":"demo","payload":{"message":"hello"}}`; `GET /query?object_id=demo`. WebSocket `/subscription?object_id=demo` получает новые события; клиент должен посылать `ping` не реже 60 секунд и может завершить подписку сообщением `complete`. Подключение с браузера с произвольным Authorization-заголовком потребует отдельного клиента.

## Масштабирование и ограничения

PostgreSQL используется как общий журнал событий: разные экземпляры приложения считывают новые записи опросом. Однако ограничения соединений и частоты хранятся в памяти процесса и **не являются общими для реплик**, а состояние токенов считывается только при старте. Поэтому здесь намеренно одна реплика; увеличение replicas без распределённых лимитов, механизма отзыва доступа и нагрузочных испытаний небезопасно. Для горизонтального масштабирования необходимы общие атомарные лимиты и отзыв, более эффективная доставка событий, нагрузочные тесты и расчёт пула БД. PostgreSQL в этом манифесте не реплицируется и является единой точкой отказа. PVC не заменяет резервное копирование.

Проектный путь к зрелому развёртыванию: выделенный VPN и проверка сетевых границ, mTLS на доверенном прокси без возможности его обхода, защищённый секретный менеджер, управляемый высокодоступный PostgreSQL с проверенным восстановлением, централизованные аудит и метрики, контроль выхода в сеть, затем HPA и независимое масштабирование чтения/записи после испытаний. Данный манифест ничего из этого автоматически не обеспечивает. Изменение requests/limits является настройкой ресурсов, а не автоматическим вертикальным масштабированием.

## Карта требований

Реализованы в коде: исторический запрос с курсорной пагинацией, подписка и отмена, синтетические события, статическая авторизация по объектам, журналирование, ограничение соединений и частоты на процесс, тайм-ауты, ограничение размера и минимальная метрика.

Не реализованы или требуют отдельной проверки: GraphQL и форматы проекта, `/download`, полный `/metric`, mTLS/VPN, отзыв и блокировка учётных данных без перезапуска, глобальные ограничения на несколько реплик, полноценный аудит с хранением и защитой, резервирование/восстановление, отказоустойчивость, аппаратные и организационные требования, совместимость с внешними системами и приёмочные процедуры. HTTP-обработчик проверяет размер полезной нагрузки после разбора запроса; ограничение на транспортном уровне не настроено. Секреты Kubernetes по умолчанию не являются полноценным хранилищем секретов. Режим `baseline` намеренно ослабляет авторизацию и не должен применяться вне отдельного изолированного эксперимента.

Подробные нормативные ориентиры и границы применимости — в `../gov.md`. Использование FastAPI, PostgreSQL и Kubernetes не доказывает выполнение требований документа.
