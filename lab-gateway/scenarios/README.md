# Сценарии КЦД

Сценарии предназначены только для собственного изолированного стенда с синтетическими данными. Скрипт принимает только HTTP loopback (`localhost`, `127.0.0.1`, `::1`); для Kubernetes сначала запустите `kubectl -n iar-lab port-forward svc/gateway 8000:8000`. Через этот порт отправляется тестовый трафик; не направляйте port-forward на чужой кластер или production. Для наблюдения используйте журнал шлюза и, при необходимости, Wireshark на интерфейсе loopback. В текущем стенде это открытый HTTP/WS: не используйте настоящие данные или пароли. Захват содержит токены — не публикуйте его без обработки.

## Подготовка

1. Поднимите стенд по [инструкции](../README.md). В `CLIENTS_JSON` должны быть разные клиент чтения и генератор: reader имеет доступ к `demo`, не имеет роли producer и не имеет доступа к `other`; producer имеет право записи в `demo`. Объект `other` должен отличаться от `demo`. Иначе результат проверки IDOR не имеет смысла. У обоих токены длиной не менее 16 символов.
2. Установите зависимость WebSocket: `python3 -m pip install -r lab-gateway/scenarios/requirements.txt` в отдельном окружении.
3. Укажите тестовые токены через переменные окружения `LAB_READER_TOKEN` и `LAB_PRODUCER_TOKEN` (не сохраняйте их в отчёте, команде или общей истории оболочки). Запустите из корня проекта:

```sh
python3 lab-gateway/scenarios/cia.py --output /tmp/iar-cia-secure.json
```

Для повторного запуска выберите другое имя файла: существующий отчёт не перезаписывается. `--object` и `--other-object` задают соответствующие объекты; `--connection-limit` должен равняться `MAX_CONNECTIONS_PER_CLIENT` конкретного процесса (по умолчанию 4); `--samples` — от 1 до 20. На время эксперимента используйте одну реплику, без других клиентов: счётчики приложения локальны для процесса. При ограничении частоты дождитесь сброса окна между прогонами. Время и результаты в JSON не содержат токенов или полезной нагрузки.

## Проверки и интерпретация

| КЦД | Сценарий | Условие PASS | Связь |
|---|---|---|---|
| Конфиденциальность | HTTP/WS без токена | HTTP 401 / отклонённый WS handshake 403 | T1 |
| Конфиденциальность | Чужой объект в `/query` и `/subscription` | HTTP 403 / отклонённый WS handshake 403 | T2 |
| Целостность | Публикация клиентом без роли | HTTP 403 | права записи |
| Целостность | Некорректный JSON | HTTP 422 | T10 |
| Целостность | Записать уникальное событие и прочесть через историю и WS | id и синтетическая полезная нагрузка совпадают | доставка и сохранность |
| Доступность | Payload больше 4096 байт | HTTP 413 | T7; ограничение полезной нагрузки после разбора JSON |
| Доступность | Открыть разрешённое число WS и попытаться открыть ещё одно | лишнее соединение отклонено; подтвердить `connection_limited` в журнале | T4/T5; одна подписка на соединение |
| Доступность | Несколько контрольных запросов после негативных проверок | каждый HTTP 200; p50/p95 записаны в мс | работоспособность после проверок |

Для сравнения baseline и secure запускайте **те же проверки** в двух отдельно развёрнутых изолированных средах с одинаковыми настройками и данными; не ослабляйте защищённую среду. Здесь PASS означает выполнение защитного ожидания, поэтому при обнаружении IDOR baseline даст FAIL — это ожидаемое выявление проблемы, а не ошибка скрипта. Перед сравнением зафиксируйте конфигурацию, аппаратные ресурсы, число реплик, фоновые клиенты, версию образа и число повторов. Показатели задержки — наблюдения, а не нормативные пороги; пять запросов не являются статистически надёжной нагрузочной оценкой.

Коды выхода: 0 — все проверки PASS; 1 — есть FAIL; 2 — ошибка подготовки/соединения или SKIP из-за отсутствия библиотеки WebSocket. При ошибке до начала проверки создаётся отчёт с полем `error` там, где удалось открыть файл. Не считайте отказ соединения доказательством авторизации: для WebSocket проверяется конкретный статус handshake, а его причину нужно подтвердить в журнале.

## Что не проверяется

TLS/mTLS, VPN, доступ извне кластера, криптографическая целостность в канале, изменения прав на действующей сессии, replay, подмена токена, rate/message flooding, idle timeout, backpressure, CSWSH и GraphQL не покрыты. Сценарий не измеряет потерю событий при перегрузке, устойчивость БД, восстановление из резервной копии и распределённые лимиты. Тест идентичности payload не доказывает защиты от изменения данных в БД или сети. Для T4/T5 отказ handshake с кодом 403 сам по себе не отличает лимит от иной причины — сопоставьте время с журналом. Применимость других угроз и нормативных требований устанавливается отдельно.

## Автоматический E2E: две изолированные среды

Для сквозного прогона нужен запущенный Docker Desktop с Docker Compose, доступ к образам `python:3.12-slim`, `postgres:16` и пакетам Python, а также достаточно места для сборки. Kubernetes и локальные Python-зависимости не нужны. Из корня проекта:

```sh
python3 lab-gateway/scenarios/e2e.py --output-dir ./lab-gateway/e2e-results-01
```

Укажите новое имя каталога при каждом запуске. Скрипт последовательно создаёт два уникальных Compose-проекта, собирает образы, поднимает отдельную временную PostgreSQL и шлюз, ждёт готовности, выполняет HTTP и WebSocket-проверки, записывает `baseline/report.json`, `secure/report.json` и `summary.json`, затем удаляет созданные контейнеры и тома. База хранится в tmpfs. Случайные лабораторные токены и пароль создаются на каждый запуск и не входят в отчёты. Тестер разделяет сетевое пространство с контейнером шлюза: внешние порты не публикуются. Docker-образы остаются в локальном кеше. Если процесс прерван принудительно, может понадобиться вручную удалить соответствующий проект с префиксом `iar-e2e-`.

В итоговом `summary.json` для baseline ожидаются ровно два FAIL — доступ к чужой истории и чужой подписке. Это демонстрация намеренного IDOR. Для secure ожидаются только PASS. Любой пропуск, ошибка запуска, отсутствующий сценарий или неожиданный результат означает ненулевой код возврата. Запуск не доказывает полное соответствие нормативным требованиям и не тестирует Kubernetes-манифест или сетевую изоляцию кластера. Зависимость от внешних реестров и интернет-доступа нужна при первой сборке.
