# План проекта

## Этап 1 — начало октября

Результат:

- утвердить состав команды;
- утвердить тему;
- сформулировать цель, задачи и гипотезу;
- зафиксировать архитектуру MVP;
- выбрать 6–8 основных сценариев угроз;
- определить стек;
- создать репозиторий и базовый Docker Compose.

## Этап 2 — октябрь

Разработка MVP:

- PostgreSQL;
- тестовые модели User / Operation / AuthorizationEvent;
- HTTP endpoint исторического поиска;
- WebSocket endpoint подписки;
- генератор тестовых событий;
- базовая аутентификация;
- структурированные логи.

Параллельно:

- определить активы;
- определить доверительные границы;
- составить модель нарушителя;
- описать поверхность атаки.

## Контрольная точка — начало ноября

Показать:

- работающий MVP;
- WebSocket subscription;
- получение события клиентом;
- первичную модель угроз;
- минимум 3 воспроизводимых слабости базовой конфигурации;
- план защитных мер.

## Этап 3 — ноябрь

Реализовать hardened-версию:

- tunnel-only access;
- mTLS/X.509;
- авторизацию уровня объекта;
- rate limits;
- connection/subscription limits;
- message size limits;
- heartbeat + idle timeout;
- обработку backpressure;
- audit log;
- безопасные ошибки.

Добавить автоматические тесты защиты.

## Этап 4 — конец ноября

Провести повторные эксперименты и оформить сравнение:

- доступность endpoint извне;
- unauthorized access;
- IDOR;
- connection flood;
- subscription flood;
- oversized payload;
- idle connections;
- malformed input.

Зафиксировать результаты таблицей Before / After.

## Этап 5 — начало декабря

Подготовить:

- отчёт 10–15 страниц;
- презентацию;
- демонстрационный сценарий на 2–4 минуты;
- выступление до 10 минут;
- резервную запись демонстрации на случай проблем со стендом.
