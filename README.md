# Проект по ИАР

Учебный проект по предмету «Информационно-аналитическая работа», связанный с информационной безопасностью, безопасной разработкой и снижением регуляторных рисков при организации удалённого доступа к данным.

## Рабочая тема

**Снижение регуляторных рисков при разработке защищённого шлюза удалённого доступа к данным**

Подзаголовок: **Исследование WebSocket-взаимодействия, туннелирования и механизмов защиты.**

## Идея проекта

1. Реализовать минимальный рабочий прототип удалённого доступа к данным через WebSocket.
2. Построить модель угроз для базовой реализации.
3. Воспроизвести контролируемые сценарии атак на собственный стенд.
4. Спроектировать и реализовать меры защиты.
5. Сравнить базовую и защищённую версии.

Итоговая версия должна включать защищённый WebSocket, туннелирование/сетевую изоляцию, усиленную аутентификацию и авторизацию, ограничения ресурсов и журналирование.

## Учебные требования

- Команда: 1–3 человека.
- В начале октября: состав команды, тема, план проекта.
- В начале ноября: статус MVP.
- В начале декабря: защита.
- Оценка командная: проект + доклад + презентация.
- Письменный отчёт: 10–15 страниц.
- Выступление: до 10 минут, один докладчик.

## Базовая архитектура MVP

```text
Test Client / ПУ
       |
       | HTTP / WebSocket
       v
Security Gateway
  /query
  /subscription
       |
       v
Information System
       |
       v
PostgreSQL
```

Минимальные сущности:

- User
- Operation
- AuthorizationEvent

## Финальная архитектура

```text
Test Client / ПУ
       |
       v
VPN / protected tunnel
       |
       v
Firewall / ACL
       |
       v
mTLS (X.509)
       |
       v
WebSocket Gateway
  - Authentication
  - Authorization
  - Origin/session validation
  - Rate limiting
  - Connection/subscription limits
  - Message size limits
  - Heartbeat/timeouts
  - Audit/monitoring
       |
       v
Application / Database
```

## Основной исследовательский цикл

```text
MVP
 -> Threat modeling
 -> Security testing
 -> Findings
 -> Security requirements
 -> Hardened implementation
 -> Re-test
 -> Before/After comparison
```

## Ключевая гипотеза

Использование только WebSocket/TLS и базовой прикладной аутентификации недостаточно для защищённого удалённого доступа к чувствительным данным. Многоуровневая модель, включающая сетевую изоляцию, туннелирование, взаимную сертификатную аутентификацию, авторизацию, ресурсные ограничения и аудит, должна заметно уменьшить поверхность атаки и регуляторные риски.
